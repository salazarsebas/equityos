# Contracts

Foundry project with the EquityOS onchain contracts.

| Contract        | Source                  | Purpose                                                |
| --------------- | ----------------------- | ------------------------------------------------------ |
| `IndexRegistry` | `src/IndexRegistry.sol` | Append-only registry of versioned index specifications |
| `RebalanceLog`  | `src/RebalanceLog.sol`  | Stateless event emitter for declared rebalances        |

Interfaces for integrators are in `src/interfaces`.

- Design: [docs/architecture/index-registry.md](../docs/architecture/index-registry.md)
- Security: [docs/security/index-registry.md](../docs/security/index-registry.md)

**These contracts have not been audited.**

## Requirements

- [Foundry](https://getfoundry.sh) 1.5.1: `foundryup --install v1.5.1`.
- Submodules: `git submodule update --init --recursive`.

The compiler (solc 0.8.39), the EVM version (`prague`), the optimizer and the metadata settings are pinned in
`foundry.toml`. The deployment addresses depend on the exact bytecode, so change these settings only on purpose.

## Build and test

From this directory:

```sh
forge fmt --check
forge build
forge test
```

From the repository root, the same commands are `bun run contracts:fmt:check`, `bun run contracts:build` and
`bun run contracts:test`.

CI runs the `ci` profile, with more fuzz and invariant runs:

```sh
FOUNDRY_PROFILE=ci forge test
```

| Profile   | Fuzz runs | Invariant runs | Invariant depth |
| --------- | --------- | -------------- | --------------- |
| `default` | 256       | 64             | 100             |
| `ci`      | 10,000    | 256            | 200             |

### Test layout

| File                                 | Contents                                                                    |
| ------------------------------------ | --------------------------------------------------------------------------- |
| `test/IndexRegistry.t.sol`           | Unit tests: access control, failure paths, boundaries, lifecycle, reads     |
| `test/IndexRegistry.fuzz.t.sol`      | Fuzz tests of valid and invalid inputs                                      |
| `test/IndexRegistry.invariant.t.sol` | Stateful invariants, driven by `test/invariant/RegistryHandler.sol`         |
| `test/IndexRegistry.gas.t.sol`       | Measured gas of a typical and of the largest possible publish               |
| `test/RebalanceLog.t.sol`            | Unit and fuzz tests of the log                                              |
| `test/IndexConsumer.t.sol`           | A third-party contract (`test/examples/IndexConsumer.sol`) reading an index |
| `test/Bytecode.t.sol`                | Opcodes that must not appear in the compiled contracts                      |
| `test/Deploy.t.sol`                  | The deployment script, run against the local test chain                     |
| `test/deploy-local.sh`               | The deployment script broadcasting to a local Anvil node                    |
| `test/Setup.t.sol`                   | Guards the toolchain configuration                                          |

### TypeScript ABI

`packages/contracts-abi` holds the ABI of both contracts as typed TypeScript modules, generated from the build
artifacts, and the deployment addresses. After a change to an interface, from the repository root:

```sh
bun run contracts:build
bun run --filter @equityos/contracts-abi generate
```

`bun run test:integration` fails while the committed modules differ from the artifacts, and a test in the package
compares its addresses with the `EXPECTED_*` constants of `script/Deploy.s.sol`. The full local workflow is in
[docs/development/local-chain.md](../docs/development/local-chain.md).

### Gas snapshots

`test/IndexRegistry.gas.t.sol` writes its measurements to `snapshots/IndexRegistry.json`, which is committed.
Running the tests rewrites the file. To fail instead when a value differs, as CI does:

```sh
FORGE_SNAPSHOT_CHECK=true forge test
```

From the repository root, `bun run contracts:snapshot` regenerates the file and `bun run contracts:snapshot:check`
verifies it. The file is generated by Forge, so `biome.json` in this directory excludes it from formatting.

### Coverage

```sh
mkdir -p coverage
forge coverage --report summary --report lcov --report-file coverage/lcov.info   --no-match-path 'test/{Deploy,Bytecode,IndexRegistry.gas}.t.sol' --no-match-coverage '^(test|script)/'
bun ../scripts/check-contracts-coverage.ts coverage/lcov.info
```

Coverage builds without the optimizer, which changes the bytecode. The three excluded files assert facts about
the optimized bytecode (code hashes, opcodes, gas) and do not hold under that build. The second command fails when
line or branch coverage of any file under `src/` is below 95%. CI runs both.

### Static analysis

CI runs [Slither](https://github.com/crytic/slither) 0.11.6 and [Aderyn](https://github.com/Cyfrin/aderyn) 0.6.8
on `src/` and compares both reports with the reviewed baseline in `static-analysis/baseline.json`:

```sh
slither . --config-file slither.config.json --json slither.json
aderyn . --output aderyn.json
bun ../scripts/check-static-analysis.ts --baseline static-analysis/baseline.json   --slither slither.json --aderyn aderyn.json
```

A finding that is not in the baseline, a baseline entry that is no longer reported and a High or Medium finding
that is not a false positive all fail the check. Every entry carries a verdict and its reason. The triage is in
[docs/security/static-analysis.md](../docs/security/static-analysis.md). Aderyn does not build on Windows.

## Deployment

`script/Deploy.s.sol` deploys both contracts with CREATE2 through the deterministic deployment proxy at
`0x4e59b44847b379578588920cA78FbF26c0B4956C`. The script:

1. Accepts only Base mainnet (8453), Base Sepolia (84532) and a local development chain (31337). On Base
   mainnet it also requires an explicit opt-in, described below.
2. Requires the proxy to have its known runtime code hash.
3. Requires the predicted addresses to equal the `EXPECTED_*` constants committed in the script.
4. Skips a contract that is already deployed, after checking its runtime code hash. Running it twice is safe.
5. Verifies the code hashes, the constants, an empty registry on first deployment, the registry address stored
   in the log, and that the deployment moved no ETH.
6. Prints the chain id, the addresses and the commit passed in `GIT_COMMIT`.

The script contains no key and reads none from the environment: the sender is chosen on the command line.

The `EXPECTED_*` constants are tied to the bytecode of the commit. After an intended change to the contracts or
to the compiler settings, `test_ExpectedConstantsMatchTheBuild` fails and prints the new values to copy into the
script.

### Local deployment

Anvil includes the deployment proxy and exposes unlocked development accounts, so no private key is needed:

```sh
anvil
```

In another terminal, from this directory:

```sh
GIT_COMMIT=$(git rev-parse HEAD) forge script script/Deploy.s.sol \
  --rpc-url http://127.0.0.1:8545 \
  --broadcast \
  --unlocked \
  --sender 0xf39Fd6e51aad88F6F4ce6aB8827279cffFb92266
```

The sender is the first default Anvil account. A second run prints `already deployed, skipped` for both
contracts and sends no transaction.

To simulate without sending anything, drop `--broadcast`, `--unlocked` and `--sender`.

### Broadcast test

`forge test` runs the script inside the test EVM (`test/Deploy.t.sol`), where `vm.startBroadcast` sends nothing.
The path that sends real transactions is covered by a shell test, which CI runs after the Solidity tests:

```sh
./test/deploy-local.sh
```

From the repository root: `bun run contracts:test:deploy`. It starts Anvil on port 8555 (override with
`ANVIL_PORT`), runs the script with `--broadcast` from the unlocked development account, and checks that the
first run sends exactly two transactions, that the code at both expected addresses has the expected hash, and
that a second run sends none. No private key is stored or passed.

### Mainnet opt-in

On Base mainnet (chain id 8453) the script reverts with `MainnetNotConfirmed` unless the environment variable
`DEPLOY_MAINNET` is set to `true`:

```sh
DEPLOY_MAINNET=true forge script script/Deploy.s.sol --rpc-url <base mainnet rpc> ...
```

The variable is read only on chain 8453. It does not unlock any other chain, and it is not needed on Base
Sepolia or locally. Calling `deploy(bool)` directly with `--sig` is the same opt-in, given as an argument.

### Live networks

Neither contract is deployed on a live network yet. The full runbook, with verification on Basescan or Sourcify
and the post-deployment checks of `script/check-deployment.sh`, is
[docs/development/deployment.md](../docs/development/deployment.md). Before a live deployment:

- Deploy on Base Sepolia first and check that the addresses equal the `EXPECTED_*` constants.
- Run a create, publish, deprecate and read-back round trip there.
- Build from a tagged commit and record the tag next to the addresses.
- Take the deployment block numbers from the transaction receipts: the block number the script prints is the
  block of the simulation.
- Verify the sources on the block explorer with the exact settings in `foundry.toml`.
